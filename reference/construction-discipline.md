# 工程约束：施工期持续对照

本文件不是施工顺序，**每次改变目标、采纳偏离、声称通过和提交前**都要按相应条目核对。适用于大小项目；项目的用户裁决、Accepted ADR 和现有指令优先于通用默认值。不要为了执行这里的检查而反复扫描已无变化的文件。

## 1. 不得把页面级源级迁移降为换皮

- **可见结构权威**：用户签收的原型版本中的 template、页面级 styles、区域顺序、组合、折叠、浮层、模式切换与动作位置；只读原型的获准视觉提案须与原版本一同记录。源码不可得时不能宣称源级移植，先向用户请求源码或裁决改成独立视觉重建任务。
- **事实与命令权威**：正式 contracts、服务、HTTP、URL、权限、错误语义和状态机；无正式来源的字段不从 mock 或猜测补值。
- 可以保留旧行为资产，但不能因为旧宿主“看着差不多”而把它当页面结构起点。保留一段旧呈现须经过真实对照证实同构，并在底账注明。
- 写了 adapter、组件或时间线不等于实现。检查导入、渲染、具体状态的浏览器复演；无人调用的实现计为未完成。
- 页面 owner 的结束语必须指向**整页**证据，不把子组件分别通过推成整页通过。

## 2. 证据责任与反连续自证

- 类型检查、单测、构建、代码行数和自行浏览正式页面是必要时的**行为／程序证据**，不能独自证明视觉和交互保真；截图相似也不能证明写命令或权限正确。
- 主 agent 操作浏览器、采集截图、复演与签署结果；不参与该区域实现的审阅者**只读已采好的截图**。子 agent 不能用组件测试代替浏览器证据，也不能宣告自己做的区域视觉通过。
- 给独立审阅者：原型／正式两张图片路径、**各自对应的固定修订**（只读提案时还要原版本 + 提案版本）、视口、页面状态、可比数据说明和原型区域定位。不给“已经接近”“我认为过了”的先行结论。审阅者须先判两图是否可比，再指出具体差异与用户最可能先发现的遗漏；正式侧改动导致证据失效时重新采受影响状态。
- 一个状态一次独立审阅；审阅者指出实质缺陷时先修、重新采图再审，不通过多派审阅者投票消掉不利结论，也不由实施者自行覆盖。没有受影响的结构变化时，不为了形式重复每片审阅。若无法委派独立审阅者，说明缺口并询问用户是否亲自并排核对；未确认前不标视觉门通过。
- 结构门在骨架成形时执行；收口再审整页。只改读写接线时用相关行为门，布局或交互结构改变则重新审阅受影响状态。**测试与截图各管一件事**，不要让两者互相背书。

## 3. 偏离、用户裁决和明确欠账

- 原型缺正式必需行为、正式合同无法呈现原型展示字段或用户改变目标时，只停止**该可见偏离**的正式侧施工；有修改权限且获准时，从当前页面签收版本创建隔离的原型缺陷分支，只承载待裁决差异并固定候选 commit；原型只读时用独立可视提案和记录版目标供用户确认，不谎称原型源码已变。源码不可得仍阻塞源级移植。技术适配由 agent 决定，体验取舍由用户决定。
- 页面签收版本是精确 commit、tag 或不可变快照，不是分支名。用户拒绝候选时原签收版本不变；用户确认目标并授权更新基线后，原型缺陷分支上的精确 commit 可直接成为该页面的新签收版本，不要求先合入原型主分支。其他未签收改动不自动生效。
- 用户裁决覆盖原要求时，在当前任务票记：旧条款、新口径、影响的实现／测试和唯一去向。直接弱化或删掉被撤销要求的执行清单，不保留两套互斥义务。
- 暂时不能消解的红测、接口缺口、不可比截图与未复演分支要显式标“未验证／阻塞／不适用”并注明依据；静态展示、无交互或纯呈现区域可标不适用，不制造命令或假复演；不能静默删除测试或把失败当通过。工程门与后续用户签收分别记录，不能要求用户先签收未建好的正式页面。
- 改写绑定旧 UI 的测试时保留其**行为主张**，只改变观察面；纯 DOM/组件私有结构断言可以删除，但要给删除理由。不存在存量测试的项目无需制造分诊文件。

## 4. 工具／环境故障的退路

- 截图通道失败时先核对标签页、视口、帧是否陈旧；同一根因重复失败两次就停止无界重试，报告受影响证据和已尝试的恢复。可改用另一个已授权浏览器通道；若仍无法采到可比图，**询问用户是否用本人现场并排确认代替截图审阅**，并记下豁免范围。用户未批准前，该视觉门仍是未验证，不标通过。
- 小项目一条命令能跑就用一条命令；复杂项目复用现有测试环境。**所有写入副作用**都先列明目标和权限：测试 fixture、迁移／种子／清理脚本、浏览器点击命令、真实请求及状态回读、原型修订均可能改变共享状态；获准隔离目标前不执行写入。别把共享数据当走查样本。
- 环境故障不是产品回归，也不是功能通过的理由。构建产物必须对应当前源码与依赖：旧 schema dist、新 web dist、错误镜像或错身份都可能产出假失败／假通过。
- 用户确认候选目标、授权候选成为新页面签收版本、将原型缺陷分支合入或推送原型主分支、发布预览／部署、改冻结文档分别授权，不相互推定。

## 5. 结束前的反证自检

只回答**当前页面**需要的几项，提供链接或路径，不做每片十二问仪式：

1. 真实原型与正式页面在相同状态、视口和可比数据下是否都看过？若没看过，哪道门尚未验？
2. 原型区域是否逐项映射到正式 DOM；是否有写出却没接入的代码？
3. 成功态结构是从原型来的，还是旧宿主上的重写？未经批准的差异有哪些？
4. 本页面实际有正式命令／URL／权限／错误吗？有则其证据是否独立于视觉证据，无则是否明确不适用？
5. 用户看到两页并排时最可能发现的遗漏是什么？它已修复、已批准还是未验证？

无法回答就如实报告“未验证”及其后果，并请用户裁决，不假完成，也不因不确定无限期不报告进度。
