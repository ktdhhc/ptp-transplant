# 工程规划：一页从原型到正式

本文件在**每张页面票开工时读一次**，用来安排工作，不是每次改代码都重新执行的仪式。具体禁止事项、证据责任及声明门见 [工程约束](construction-discipline.md)。页面范围可以小，步骤可合并；不能跳过“原型是什么／正式事实是什么／如何证明接上了”的核对。

## 0. 取证并界定范围

1. 核对分支、工作区与其他并行任务，不覆盖未提交文件；取得用户指定的原型固定版本。检查它是否包含页面和必要交互，不把“分支最新”自动视为签收源。核实源码可否取得和读取，另行核实能否修改；没有源码时源级移植阻塞，请用户提供源码或选择另立视觉重建目标，不自行把看图重写算作源级移植。
2. 找到正式产品的最小运行路径：纯静态页面可能一条命令即可；复杂系统再核对 API、隔离库与 worker。列出**所有**写入副作用（测试 fixture、脚本、浏览器命令、回读、原型版本变更，以及随真实请求外发的通知或第三方触发等）及各自授权与隔离目标；未获授权不执行写入。
3. 用 [原型区域清单模板](../templates/demo-regions.md)穷举页面实际存在的区域、条件分支及动作；用 [行为资产清单模板](../templates/behavior-assets.md)索引实际适用的合同、服务、状态、URL 与命令。正式行为尚未定义时请用户指定要移植的行为，先不要造接口；静态页可明确没有接线行为。
4. 将区域与行为合并为一份 [移植底账](../templates/transplant-ledger.md)：每个原型区域有唯一正式 owner；交互复演项归属区域，证据在同行或紧邻子表。不要分别维护两份进度表。
5. **条件分诊**：如果存在绑定待替换视图的存量测试，按 [测试分诊模板](../templates/test-triage.md)逐条 keep/adapt/delete。没有存量测试则跳过，不为了模板造空文件。
6. 对已经批准的差异注明来源；对未决可见差异先走下文的旁路（可编辑原型用缺陷分支，只读原型用独立提案），不在正式页猜结果。

开始源级施工前，至少要能回答：页面区域是否完整、每个区域去哪个正式目标、哪些正式行为必须存活（或明确无）、签收版本及源码可否取得、测试与所有可写走查如何隔离执行。缺原型源码的阻塞不妨碍准备清单，但不能进入源级骨架移植。小票可在票面用短表承载，不按文件数评价准备质量。

## 1. 先移植成功态页面骨架

取得可读取的签收原型源码后，以其 template、页面级 styles、区域顺序与组合方式为起点，复制成功态页面骨架。正式读取错误、非法身份、return target 等宿主状态可在成功态外层保留；**成功态的页面结构不能以旧正式视图为源**。先用可重复的占位数据验证区域和几何，不把 mock service 或演示 store 移入生产路径。骨架只需具备待接线区域的容器／位置和必要视觉状态；无需先完成尚未接入的命令、URL、权限和数据流，避免骨架门依赖后续接线。

在骨架结构稳定时执行一次结构门：按目标设备选定代表视口，用同视口、同状态、语义对应数据的原型与正式构建产物对照；若产品明确覆盖桌面与较窄窗口，则分别取样。每对截图记原型**签收版本**和正式侧**源码／构建修订**（以及视口、状态、数据口径）；正式侧之后变化须按影响范围更新证据。主 agent 采图；独立审阅者只读两边截图，列出缺失区域、顺序、折叠、密度和动作位置，主 agent 将结果写入底账。**验收结构和待接线区域占位，不在占位期伪称正式行为已成立**。

结构门失败就在骨架上修，不带着差异进入大量接线。截图能力故障遵循工程约束的故障退路，不能把缺图记为通过。

## 2. 按区域纵向接线

把正式 contracts、services、composables、URL、权限和命令经最薄的 view-model／adapter 接到已成形的区域。切片粒度是“一个区域到正式事实的一条可验证路径”，不是每个视觉小块一张独立签收票。可并行实现不共享写资源的纯适配切片；页面 owner 负责集成与浏览器门。

按页面实际存在的区域及依赖选顺序，例如身份、列表／阅读、筛选／详情、写命令与边界态；静态展示页可以没有行为接线，不因示例列表添加调试、详情或写命令。

每片只跑**受影响范围内有意义**的验证：行为逻辑优先相关测试，类型或构建会受影响时再运行对应检查；对新增或改变的 contract/schema、service 映射、view-model、URL、资格矩阵、错误分类、状态转换与命令 binding，适合先写失败测试再实现。纯模板与 CSS 不用写 DOM 细节单测。已复用且未改的服务不为制造形式上的 red 重写同义测试。

接线过程中不对每片机械重跑双视口截图。但**只要改动了已验过的布局、区域顺序、折叠、浮层位置或动作位置**，对受影响状态重新取图审阅。进度由移植底账记录：写了 adapter 但页面没有 import/render/复演，仍是未接线或未走查；不靠 commit 数报完成。

### 横向旁路：原型缺陷与正式要求冲突

任一切片发现原型缺控件、正式契约不能表达原型事实、权限与演示行为冲突或新的产品裁决影响可见结构时：

1. 记录冲突、影响区域、正式依据及用户可选择的目标；必要时通过 grilling 对齐，而不是代用户拍板。
2. **能修改且获准修改原型**：在隔离的缺陷分支形成可观看目标状态；不用 git 的项目保留等效不可变快照。**只读原型**：以独立可视提案／标注截图呈现目标状态和差异，记录原型原版本 + 提案固定版本；不得声称修改了原型源码，也不把提案冒充原型分支。无源码时源级移植仍阻塞，提案不能替代源码。
3. 用户实际看过并确认**目标状态**后，记录其依据与精确版本（可编辑时为新原型版本；只读时为原原型版本加获准提案版本）；校准受影响的区域、底账和交互项，再同步正式页。仅获准改动进入签收范围。
4. 在当前任务票记用户裁决覆盖哪些旧要求、哪些测试必须重分诊；未确认内容不合入正在维护的原型主分支，也不进入正式侧可见结构。

这条旁路可以在骨架前或任一切片触发，不是施工后才补的“例外许可”。只有具备修改权限且另获授权时才谈原型主分支回写；用户确认目标状态不自动授权合并／推送。

## 3. 收口时集中核对

接线完成后统一做一次整页视觉复核：默认态及**该页面实际具有**的关键状态（例如展开态、权限态）；静态展示页不制造调试或详情态。主 agent 采同视口同状态、绑定两侧修订的截图，交给未参与相应实现的审阅者寻找反证。工程门完成后提供证据邀请用户在浏览器里操作实际存在的目标路径；用户签收是后续交付门，不是工程门的先决条件。复核发现的可见变化按“正式事实差异／已批准偏离／未批准漂移”分类，不能用一张不同状态的截图硬比。

沿底账中实际存在的交互子项逐条真实复演；静态展示或纯呈现区域明确标不适用，不凑通过数。浏览器能力缺失时需浏览器的交互项保持待复演，报告阻塞并问用户是否继续其他工作；测试通过不能替代交互门。**所有写入副作用**（测试、脚本、浏览器命令及回读）都须先核对授权与隔离目标，有写路径的页面在获准隔离环境串行真验请求、状态回读、权限阻断和 URL；无写行为页面不造写路径。最后跑一次受影响范围的完整行为回归，跨包契约变化或票组收口时再考虑全量。

收口记录至少包含：结构证据及两侧修订、适用的行为测试命令/结果、实际交互复演、获准的真实写入证据（无写路径标不适用）、未验证项、批准偏离及**独立的**用户签收状态。截图门出故障时按纪律将缺口公开交给用户处理；用户没签收则页面交付保持未完成，已完成的工程门照实记录。仅在持有原型修改权限且获另行授权时考虑合回原型缺陷分支；提交与推送也另行授权，不默认开始下一页。
