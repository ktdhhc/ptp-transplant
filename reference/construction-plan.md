# 工程规划：一页从原型到正式

本文件在**每张页面票开工时读一次**，用来安排工作，不是每次改代码都重新执行的仪式。具体禁止事项、证据责任及声明门见 [工程约束](construction-discipline.md)。页面范围可以小，步骤可合并；不能跳过“原型是什么／正式事实是什么／如何证明接上了”的核对。

## 0. 取证并界定范围

1. 核对分支、工作区与其他并行任务，不覆盖未提交文件；取得用户指定的原型固定版本。检查它是否包含页面和必要交互，不把“分支最新”自动视为签收源。
2. 找到正式产品的最小运行路径：纯静态页面可能一条命令即可；复杂系统再核对 API、隔离库与 worker。确认会触发写入的动作及授权边界。
3. 用 [原型区域清单模板](../templates/demo-regions.md)穷举页面区域、条件分支及动作；用 [行为资产清单模板](../templates/behavior-assets.md)索引合同、服务、状态、URL 与命令。正式行为尚未定义时请用户指定要移植的行为，先不要造接口。
4. 将区域与行为合并为一份 [移植底账](../templates/transplant-ledger.md)：每个原型区域有唯一正式 owner；交互复演项归属区域，证据在同行或紧邻子表。不要分别维护两份进度表。
5. **条件分诊**：如果存在绑定待替换视图的存量测试，按 [测试分诊模板](../templates/test-triage.md)逐条 keep/adapt/delete。没有存量测试则跳过，不为了模板造空文件。
6. 对已经批准的差异注明来源；对未决可见差异先走下文的原型缺陷分支，不在正式页猜结果。

开始编码前，至少要能回答：页面区域是否完整、每个区域去哪个正式目标、哪些正式行为必须存活、签收版本可否重现、测试与可写走查如何执行。小票可在票面用短表承载，不按文件数评价准备质量。

## 1. 先移植成功态页面骨架

以签收原型的 template、页面级 styles、区域顺序与组合方式为起点，复制成功态页面骨架。正式读取错误、非法身份、return target 等宿主状态可在成功态外层保留；**成功态的页面结构不能以旧正式视图为源**。先用可重复的占位数据验证区域和几何，不把 mock service 或演示 store 移入生产路径。

在骨架结构稳定时执行一次结构门：按目标设备选定代表视口，用同视口、同状态、语义对应数据的原型与正式构建产物对照；若产品明确覆盖桌面与较窄窗口，则分别取样。主 agent 采图；独立审阅者只读两边截图，列出缺失区域、顺序、折叠、密度和动作位置，主 agent 将结果写入底账。**验收结构，而不是在静态占位期伪称正式行为已成立**。

结构门失败就在骨架上修，不带着差异进入大量接线。截图能力故障遵循工程约束的故障退路，不能把缺图记为通过。

## 2. 按区域纵向接线

把正式 contracts、services、composables、URL、权限和命令经最薄的 view-model／adapter 接到已成形的区域。切片粒度是“一个区域到正式事实的一条可验证路径”，不是每个视觉小块一张独立签收票。可并行实现不共享写资源的纯适配切片；页面 owner 负责集成与浏览器门。

建议顺序：对象头与身份 → Run/对象索引与时间线 → 主要阅读面 → 调试与筛选 → Inspector／详情下钻 → Composer／写命令 → 边界态。实际依赖决定顺序，不为服从列表倒置工程依赖。

每片只跑**受影响范围内有意义**的验证：行为逻辑优先相关测试，类型或构建会受影响时再运行对应检查；对新增或改变的 contract/schema、service 映射、view-model、URL、资格矩阵、错误分类、状态转换与命令 binding，适合先写失败测试再实现。纯模板与 CSS 不用写 DOM 细节单测。已复用且未改的服务不为制造形式上的 red 重写同义测试。

接线过程中不对每片机械重跑双视口截图。但**只要改动了已验过的布局、区域顺序、折叠、浮层位置或动作位置**，对受影响状态重新取图审阅。进度由移植底账记录：写了 adapter 但页面没有 import/render/复演，仍是未接线或未走查；不靠 commit 数报完成。

### 横向旁路：原型缺陷与正式要求冲突

任一切片发现原型缺控件、正式契约不能表达原型事实、权限与演示行为冲突或新的产品裁决影响可见结构时：

1. 记录冲突、影响区域、正式依据及用户可选择的目标；必要时通过 grilling 对齐，而不是代用户拍板。
2. 在与原型主分支隔离的**缺陷分支**形成可观看的目标状态；只有用户批准的改动进入本页面的签收链。若项目不使用 git，保留等效不可变版本快照。
3. 用户实际看过并确认后，原子记录精确签收版本；校准受影响的区域清单、移植底账和交互项；再把变化同步正式页。
4. 在当前任务票记用户裁决覆盖哪些旧要求、哪些测试必须重分诊；未确认内容不合入正在维护的原型主分支。

这条旁路可以在骨架前或任一切片触发，不是施工后才补的“例外许可”。回写到原型主分支是**后续明确的集成步骤**，不能把“用户确认某页面版本”自动当作合并／推送许可。

## 3. 收口时集中核对

接线完成后统一做一次整页视觉复核（至少默认阅读、调试与详情展开，以及页面特有的关键状态）；由主 agent 采同视口同状态截图，交给未参与相应实现的审阅者寻找反证。用户在浏览器里实际点击最终目标路径。复核发现的可见变化按“正式事实差异／已批准偏离／未批准漂移”分类，不能用一张不同状态的截图硬比。

沿底账中的交互子项逐条真实复演；无关项目明确标不适用，不凑通过数。有写路径的页面在**获准的隔离环境**串行真验请求、状态回读、权限阻断和 URL；静态原型或无写行为页面不造写路径。最后跑一次受影响范围的完整行为回归，跨包契约变化或票组收口时再考虑全量。

收口记录至少包含：结构证据、行为测试命令/结果、交互复演、真实写入证据、未验证项、批准偏离及用户签收。截图门出故障时按纪律将缺口公开交给用户处理；用户没签收则状态保持未完成。完成后按用户授权决定是否合回原型缺陷分支、提交与推送；不默认开始下一页。
