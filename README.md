# ptp-transplant

**Prototype to Production Transplant**：一个协助 AI Agent 把已确认的交互原型接到正式应用上的 Skill 项目。它针对“原型好看、后端已有、但反复接成另一套页面”的问题：把原型作为**页面可见结构的来源**，把正式 contracts、API、权限、URL 与状态机作为**事实和行为来源**，把用户实际验收作为完成条件。

目前是独立项目中的初稿，**不是已经完成实测的已发布 Skill**。仓库根目录不属于 Agent Hub；原项目文件不由这里修改。

## 适用场景

- 已有一个可运行的页面原型，正式应用也有可复用的后端或行为资产，需要把两者接起来。
- 旧 UI 被判废，要保留正式命令、错误语义与测试，但不希望新视图从旧壳自由生长。
- 新项目的第一版产品化：旧视图和旧测试可以没有，仍可用本 Skill 对齐目标和接线。
- 项目很小：一条命令就能运行页面时，无需为了遵循 Skill 搭数据库、worker 或生成四份长文档。

不适用于没有页面原型的从零设计，或只是换主题、改几处 CSS、无需对照用户签收原型的任务。

### 安装与试用

本仓库根目录**就是 Skill 本体**（`SKILL.md` + `reference/` + `templates/`）。安装脚本会把这三样放进 Agent 的 Skill 发现路径：

```bash
# 安装到当前项目的 .agents/skills/ptp-transplant（默认）
npx github:ktdhhc/ptp-transplant

# 安装到用户级 ~/.agents/skills/ptp-transplant（所有项目可用）
npx github:ktdhhc/ptp-transplant --global

# 先看会写到哪里，不落盘
npx github:ktdhhc/ptp-transplant --dry-run
```

选项：`--global`/`-g` 用户级安装、`--dir <path>` 指定目标、`--force`/`-f` 覆盖已存在、`--dry-run` 预演、`--help` 说明。安装后**重启该项目的 Agent 会话**，Skill 才会被发现。

若该包已发布到 npm，也可用 `npx ptp-transplant`，参数相同。也可以不用安装器：直接把本仓库复制成 `<项目>/.agents/skills/ptp-transplant/`（或 `~/.agents/skills/ptp-transplant/`），效果一样。

用户可以说“把签收的 demo 页面接到正式 Web，后端/API 已有，按 `ptp-transplant` 做”，或在支持 slash command 的宿主里显式调用 `/ptp-transplant`。Skill 应先核对 `grilling`、`to-tickets`、browser-use 和截图能力；缺失时说明影响并询问是否继续，而非静默冒充完整验收。`to-tickets` 在部分宿主只接受用户显式触发，需由用户发起 `/to-tickets`。

### 工作方式

**用户向大流程**：对齐目标和签收版本 → 立页面票与边界 → 用户在正式页面操作并签收。

**工程向小流程**：枚举原型区域与正式行为 → 建立一份“移植底账” → 从原型复制成功态骨架并验结构 → 按区域接正式事实（切片跑行为测试，不机械地每片截图）→ 统一整页复核和真实写路径复演。

原型与正式要求冲突时，先在隔离的 demo 缺陷分支做出可看的目标态，经用户确认后再更新该页面的签收版本与正式页面。这是贯穿流程的变更控制，不是允许 agent 自行扩大页面的借口。

## 最小输入与产出

输入最好包括：目标页面及原型固定版本、已有正式行为/后端入口、用户特别批准或拒绝的可见偏离、可运行方式。缺其中一项并非一律停工：小项目只要能展示页面即可先做结构；正式行为显式缺失时问清本轮到底要接哪些行为；缺浏览器或截图能力时问用户是否允许只做准备工作，不能声称通过该验收门。

产出以**一张页面票、一份移植底账、一套可运行正式页面及可追溯证据**为主。四个模板不是强制四个文件：无旧 UI 测试时不创建测试分诊；工件很短时可放进同一任务票。把区域映射与交互复演放在同一份底账，避免多份状态互相矛盾。

## 开发状态与试用建议

- 已建立 Skill 主文件、工程规划、工程约束、四个可裁剪模板和失败案例参考。
- 尚未用 2–3 个不同规模的真实项目试跑；不要把“文件已写完”误认为 Skill 已验证。
- 试用宜包括：①只有静态 demo 和一行启动命令的小项目；②已有 API/URL/写命令的大页面；③缺 browser-use 或 `to-tickets` 的能力降级情形。记录触发是否正确、是否制造不必要工件、是否遗漏整页结构、遇截图故障是否及时向用户升级。
- 本目录未因创建自动初始化 Git 或推送远端；版本管理和发布由项目维护者决定。
